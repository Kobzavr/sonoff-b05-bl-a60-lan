# Sonoff B05-BL-A60 Local LAN Controller & HTTP API (`BL602` / `UIID 136`)

Lightweight, standalone Python CLI, custom Sunrise Wake-Up Alarm, Web UI, and Local HTTP REST API for the **Sonoff B05-BL-A60** (and `B05-BL-A19` / `B02-BL`) Wi-Fi Smart LED Bulb — **without flashing custom firmware, without soldering, and without Home Assistant**.

## Hardware & Protocol Specifications

If you own a **Sonoff B05-BL-A60** (RGBCW, E27, 9W) smart bulb, it typically appears in your router's DHCP client table with the hostname **`Bouffalolab_BL602-xxxxxx`**:
* **Bulb Models:** `Sonoff B05-BL-A60`, `Sonoff B05-BL-A19`, `Sonoff B02-BL-A60`
* **Microcontroller (SoC):** **Bouffalo Lab BL602** (RISC-V Wi-Fi 2.4 GHz + Bluetooth LE)
* **LED Driver IC:** `BP5758` (I2C)
* **eWeLink Protocol Profile:** **`UIID 136`** (`type=light`, local HTTP API on `8081/TCP`, mDNS discovery `_ewelink._tcp.local.` on `5353/UDP`)

## How It Works & Why One-Time eWeLink Login Is Required

1. **Bluetooth LE is only used for initial pairing:** The eWeLink mobile app uses Bluetooth solely to pass your Wi-Fi credentials to the bulb and register it with your account. After provisioning, the bulb operates over Wi-Fi.
2. **Stock Firmware LAN Control:** Out of the box, the bulb runs a local HTTP server (`http://<IP>:8081/zeroconf/...`) and broadcasts its state via **mDNS (`5353/UDP`)**.
3. **AES-128-CBC Encryption (`devicekey`):** Because the B05-BL-A60 is not a hardware-jumper "DIY Mode" relay, all local LAN commands and mDNS state broadcasts are encrypted using **AES-128-CBC** with a unique per-device 16-character secret (**`devicekey`**).
4. **Retrieving Your `devicekey`:** The `devicekey` can **only** be obtained by logging into your eWeLink account once, as it is generated by the eWeLink cloud during device pairing. Running `python sonoff_bulb.py login` authenticates against the eWeLink Cloud API v2, downloads your `devicekey`, automatically discovers the bulb's IP via mDNS, and saves them to `bulb_config.json`.
   * Once `bulb_config.json` is saved, you can uninstall the slow eWeLink app (and even block internet access for the bulb on your router). All subsequent communication happens **100% locally over Wi-Fi in ~15–20 ms**.

## Quick Start

### 1. Install Dependencies
The script uses Python's standard library plus `cryptography` for AES-128-CBC:
```bash
pip install -r requirements.txt
```

### 2. Fetch `devicekey` & Auto-Discover the Bulb (One-Time Setup)
```bash
python sonoff_bulb.py login
```
*(By default it uses country code `+7` and region `eu`. For other countries/regions, pass `-c` and `-r`, e.g.: `python sonoff_bulb.py login -c +1 -r us` or `python sonoff_bulb.py login -c +44 -r eu`).*

Alternatively, if you already know your `devicekey`:
```bash
python sonoff_bulb.py discover
python sonoff_bulb.py set-key YOUR_DEVICEKEY --ip 192.168.0.xxx --deviceid 1001xxxxxx
```

## CLI Usage

```bash
# Query and decrypt current bulb state via local mDNS
python sonoff_bulb.py status

# Turn ON / OFF / Toggle
python sonoff_bulb.py on
python sonoff_bulb.py off
python sonoff_bulb.py toggle

# White mode: brightness (--br 1..100%) and color temperature (--ct 0..100% or --kelvin 2000..6500)
python sonoff_bulb.py white --br 80 --kelvin 4000
python sonoff_bulb.py white --br 25 --ct 0

# RGB Color mode: R G B (0..255) and brightness (--br 1..100%)
python sonoff_bulb.py rgb 255 80 0 --br 100

# Built-in hardware scenes (bright, goodNight, read, nightLight, party, leisure, soft, colorful)
python sonoff_bulb.py effect nightLight
python sonoff_bulb.py effect party
```

## Custom Sunrise Wake-Up Mode (`morning`)

The stock Sonoff B05-BL-A60 firmware does **not** include a smooth sunrise wake-up transition mode out of the box. This tool implements a **custom `morning` mode** designed for cronjobs, smart alarms, and local AI agents.

When invoked, `python sonoff_bulb.py morning` spawns a **detached background worker process** and exits immediately so your terminal, cronjob, or AI agent is never blocked:
1. **Phase 1 (First 20% of duration, e.g. 0–6 min — "Dawn"):** Starts at `1%` brightness in deep red/amber (`RGB 255, 20, 0`) and smoothly transitions to warm golden-orange (`12%`). Starting with red/amber instead of white prevents harsh glare in a dark room.
2. **Phase 2 (Remaining 80% of duration, e.g. 6–30 min — "Sunrise"):** Switches to the main white LEDs and follows a non-linear perceptual gamma curve ($\gamma \approx 1.5$), stepping every 30 seconds from `10%` warm candle light (`2000K`, `ct=0`) up to `100%` energizing morning daylight (`~5400K`, `ct=75`).
3. **Completion & Smart Cancellation:** After reaching `100%` at 30 minutes, the bulb remains **ON** and the background worker exits cleanly. Sending any manual command (`off`, `on`, `white`, `rgb`, `effect`, `toggle`) automatically cancels any running sunrise worker so it never overrides your manual action.

```bash
# Start default 30-minute sunrise in the background (leaves bulb ON at 100% when finished)
python sonoff_bulb.py morning

# Custom ramp duration (e.g. 20 minutes) or optional auto-off delay after ramp
python sonoff_bulb.py morning --ramp 20
python sonoff_bulb.py morning --ramp 30 --auto-off 30

# Check progress or stop the running background sunrise worker
python sonoff_bulb.py morning --status
python sonoff_bulb.py morning --stop
```

## Local HTTP REST API & Web Control Panel (`serve`)

Start the built-in lightweight HTTP server:
```bash
python sonoff_bulb.py serve --port 8000
```
* **Web UI Control Panel:** `http://localhost:8000/`
* **`GET /api/status`** — Returns decrypted bulb state in JSON
* **`POST /api/control`** — Unified JSON endpoint for scripts, webhooks, and local AI agents:
  * `{"state": "off"}` / `{"state": "on"}` / `{"state": "toggle"}`
  * `{"state": "morning", "ramp": 30}`
  * `{"br": 85, "kelvin": 3500}`
  * `{"rgb": [0, 140, 255], "br": 100}`
  * `{"effect": "party"}`
